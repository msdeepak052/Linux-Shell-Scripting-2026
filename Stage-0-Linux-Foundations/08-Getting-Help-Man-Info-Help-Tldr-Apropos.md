# Getting Help: `man`, `info`, `--help`, `tldr`, `apropos`

Knowing how to find the right answer fast — without leaving the terminal or guessing at flags — is what separates someone who "sort of knows Linux" from someone you trust on a production box at 2 AM.

## Explanation

**`man` (manual pages)** is the canonical, most complete reference, organized into numbered **sections**:

| Section | Contents |
|---|---|
| 1 | User commands (executable programs/shell commands) |
| 2 | System calls (kernel functions, e.g. `open(2)`) |
| 3 | Library calls (C library functions, e.g. `printf(3)`) |
| 4 | Special files (`/dev` entries, device drivers) |
| 5 | File formats and conventions (e.g. `/etc/passwd` as a **file**) |
| 6 | Games |
| 7 | Miscellaneous (protocols, conventions, macro packages) |
| 8 | System administration commands (usually root-only, e.g. `mount(8)`) |

The same name can exist in multiple sections — `passwd` is both a **command** (section 1, changes your password) and a **file format** (section 5, describes `/etc/passwd`'s structure). `man passwd` gives you section 1 by default; `man 5 passwd` explicitly asks for the file-format page. Use `man -a passwd` to page through *every* section that has a `passwd` entry.

**Navigating man pages** (they're paged through `less` by default):
- `/pattern` then `n`/`N` — search forward, next/previous match
- `space`/`b` — page down/up
- `g`/`G` — jump to top/bottom
- `q` — quit
- Standard sections inside every page: `NAME`, `SYNOPSIS`, `DESCRIPTION`, `OPTIONS`, `EXAMPLES`, `FILES`, `SEE ALSO`, `EXIT STATUS`, `BUGS`

**`info` vs `man`**: `info` pages are GNU's own hypertext-style docs — navigable with links (`n`/`p`/`u` for next/prev/up node, `Enter` to follow a link) rather than one long scroll. Some GNU tools (`gcc`, `tar`, `coreutils` like `ls`/`cp`) have more detailed, tutorial-style docs under `info` than `man`, since `man` for these is often just an auto-generated stub pointing you to `info`. In practice most sysadmins reach for `man` first and only drop into `info` when a man page literally says "see the info pages for full documentation."

**`--help`**: nearly every command supports `command --help` (or sometimes `-h`) as a fast, terse cheat sheet of just the flags/usage — no prose, no examples, generated by the program itself rather than a separate doc file. It's the fastest lookup when you already roughly know the command and just forgot a flag's spelling.

**`tldr`** (community-maintained, not built into most distros — install via package manager or `pip`/`npm`) flips the model: instead of exhaustive flag documentation, it shows 5-8 **common real-world example commands** with one-line explanations. Great for "just show me how people actually use this" instead of wading through a 400-line man page.

**`apropos`** (equivalent to `man -k`) searches the short one-line descriptions of *all* man pages for a keyword — the tool for "I know what I want to do but forgot the command name." It relies on the `mandb`/`whatis` database being built (`sudo mandb` refreshes it). `whatis command` is the narrower cousin — one-line description for an exact command name only.

## Hands-On Examples

**1. `passwd` — same name, two sections, very different content**
```bash
$ man passwd
PASSWD(1)                    User Commands                   PASSWD(1)
NAME
       passwd - change user password
SYNOPSIS
       passwd [options] [LOGIN]
...

$ man 5 passwd
PASSWD(5)                File Formats and Conversions          PASSWD(5)
NAME
       passwd - the password file
DESCRIPTION
       /etc/passwd contains one line for each user account, with seven
       colon-separated fields: ...

$ man -a passwd     # -a walks through EVERY section that matches, one after another
```

**2. `apropos` to find a command you forgot the name of**
```bash
$ apropos "list open files"
lsof (8)             - list open files

$ apropos partition
fdisk (8)            - manipulate disk partition table
parted (8)           - a partition manipulation program
cfdisk (8)           - display or manipulate a disk partition table
gdisk (8)            - Interactive GUID partition table (GPT) manipulator

# if apropos returns nothing, the database is stale/missing:
$ apropos partition
partition: nothing appropriate.
$ sudo mandb
Purging old database entries in /usr/share/man...
Processing manual pages under /usr/share/man...
...
$ apropos partition
fdisk (8)            - manipulate disk partition table
```

**3. `whatis` — exact-name one-liner, faster than opening the full page**
```bash
$ whatis grep
grep (1)             - print lines that match patterns

$ whatis ls
ls (1)               - list directory contents
```

**4. `tldr` vs `man` for `tar` — same tool, very different reading experience**
```bash
$ tldr tar
tar
Archiving utility, often used with a compression method.

- Create an archive from files:
    tar cf target.tar file1 file2 file3

- Create a gzipped archive:
    tar czf target.tar.gz file1 file2 file3

- Extract a gzipped archive into the current directory:
    tar xzf source.tar.gz

- Extract an archive into a target directory:
    tar xf source.tar -C directory

- List the contents of an archive:
    tar tvf source.tar

$ man tar
TAR(1)                    GNU TAR MANUAL                     TAR(1)
NAME
       tar - an archiving utility
SYNOPSIS
       tar [OPTION...] [FILE]...
DESCRIPTION
       GNU tar is an archiving program...
       [several hundred more lines of OPTIONS: -c, --create; -x, --extract; ...]
```
`tldr` gets you a working command in 5 seconds; `man` is what you read when `tldr`'s examples don't cover your exact case (e.g. an obscure flag like `--exclude`).

**5. `--help` for a fast flag lookup without leaving your train of thought**
```bash
$ curl --help | head -15
Usage: curl [options...] <url>
     --abstract-unix-socket <path> Connect via abstract Unix domain socket
     --anyauth       Pick any authentication method
 -a, --append        Append to target file when uploading
     --aws-sigv4 <provider1[:provider2[:region[:service]]]> AWS sigv4 signing
     --basic         Use Basic authentication
     --cacert <file> CA certificate to verify peer against
...
(use "curl --help all" for full list of options)

$ grep -h        # some tools use -h instead of --help
Usage: grep [OPTION]... PATTERNS [FILE]...
```

**6. `info` for tools whose `man` page is just a stub**
```bash
$ man gcc
GCC(1)                      GNU                      GCC(1)
NAME
       gcc - GNU project C and C++ compiler
...
       For instructions on reporting bugs, see...
       See the Info entries for gcc, or 'https://gcc.gnu.org/onlinedocs/'
       for more complete information.

$ info gcc
File: gcc.info,  Node: Top

This manual documents how to use gcc, the GNU compiler...

* Menu:
* G++ and GCC::            You can compile C or C++ programs.
* Standards::               Language standards supported by GCC.
* Invoking GCC::            Command options supported by 'gcc'.
...
```

**7. Searching WITHIN a man page (`/` search) for one specific flag**
```bash
$ man rsync
# once inside, type:
/--delete<Enter>
       --delete                delete extraneous files from destination dirs
# press 'n' to jump to the NEXT occurrence of "--delete" in the page
# press 'q' to quit back to the shell
```

**8. Combining `apropos` with `grep` to narrow noisy results**
```bash
$ apropos . | grep -i "network interface"
ip(8)                - show / manipulate routing, devices, policy routing and tunnels
ifconfig(8)          - configure a network interface
ip-link(8)           - network device configuration
```

## Practice Questions

1. You run `man crontab` and only see how to edit a user's crontab (the command), but you actually need to know the *file format* for `/etc/crontab`. What do you run instead, and why does `man crontab` default to the page it shows?
2. What does `man -k firewall` (or equivalently `apropos firewall`) actually search — the man page's full text, or something else? What do you need to run first if it returns "nothing appropriate" even though the command clearly exists on the box?
3. You forgot the exact name of the command that shows open network sockets, but you remember it relates to "network statistics." How would you find it using only `apropos`?
4. What's the practical difference between `info` and `man`, and why do some tools (like `gcc` or `tar`, from GNU coreutils) point you toward `info` for the "full" documentation instead of `man`?
5. When would you reach for `tldr tar` instead of `man tar`, and what does `tldr` deliberately leave out that `man` includes?
6. Explain the difference between `man 1 passwd` and `man 5 passwd`. Give one other real command name that similarly exists in two different man sections with two different meanings.
7. `whatis nginx` returns nothing, but `man nginx` works fine. What's the most likely reason, and how do you fix it?
8. A colleague says `--help` and `man` always show identical information. Is that true? What kind of information typically appears in a man page's `EXAMPLES`/`SEE ALSO`/`FILES` sections that `--help` output usually skips?
9. You're inside a `man` page and want to find every occurrence of the string `-exec` without re-reading the whole page top to bottom. What keystrokes do you use?
10. In a scripted/automated environment (e.g. inside a Dockerfile or a minimal CI runner), `man` and `tldr` are frequently unavailable or stripped out to save space. What's your fallback for discovering a command's flags in that situation?

## Interview Key Points

- **Man page sections are numbered 1-8** and the number matters: section 1 = user commands, section 5 = file formats, section 8 = admin/root commands. `man passwd` vs `man 5 passwd` is a classic "gotcha" interview question — know it cold.
- `apropos` (== `man -k`) searches the **short one-line NAME descriptions** in the man database, not full page text — and it depends on `mandb` being built; "nothing appropriate" often just means run `sudo mandb` first, not that the tool doesn't exist.
- `whatis` = exact command name → one-line description; `apropos` = keyword → any matching command. Know which one to reach for ("I forgot the exact name" → `apropos`; "I know the name, just want a one-liner" → `whatis`).
- `info` pages exist because GNU historically considered `man` pages secondary/summary docs — many GNU tools' `man` pages are thin stubs that explicitly say "see info for full docs." This is a common trivia point.
- `tldr` is **not part of core Linux** — it's a separate, community-maintained project/package, example-first rather than exhaustive. Don't confuse it with a built-in tool in an interview; mention it needs installing.
- `--help` is fast and always available for well-behaved CLI tools, but it's terse flag-listing only — no `SEE ALSO`, no file locations, no exit-code semantics, no deep examples the way `man`'s dedicated sections provide.
- Man pages inside `less` support `/search`, `n`/`N` for next/previous match — being unable to navigate a long page efficiently is an obvious "never actually used the terminal seriously" tell in an interview.
- For minimal/stripped-down environments (containers, embedded systems) where `man`/`info`/`tldr` may not be installed, `--help` is usually the only guaranteed fallback — worth mentioning as a real-world constraint.
